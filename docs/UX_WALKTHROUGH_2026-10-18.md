# Claim Commons 人工用户路径试用报告

日期：2026-10-18，Asia/Hong_Kong。

## 结论

六页动线已经成立，首页的字体层级也比早期版本克制。本轮不建议重做视觉风格，优先修复“能否找到已有证据、看清记录状态、核对来源”的问题。

最高优先级是混合状态筛选、不同入口的统计口径、逻辑图可读性，以及 PDF 数学符号读取质量提示。本报告未改网站代码、数据库或公开部署。

## 环境与边界

- 测试对象：本地当前版本，`http://127.0.0.1:8871/`，不是公开 GitHub Pages 版本。
- 实际桌面视口：1280 × 720。浏览器尺寸模拟没有改变实际视口，手机布局不计为已验证，也不据此提出已复现的手机缺陷。
- 首次新开页面时本地服务已停止；恢复临时静态预览后继续。这是本地预览可用性问题，不是公开站点宕机证据。
- 实际浏览首页、方法页、两个示例、知识库四个模式、论文/claim 详情、阅读报告、提取工具、社区与留言板。
- 用 Roxin 2011 已发表论文试用本地 PDF 读取、文字预览、基础 JSON 下载和缺少模型配置时的表单反馈。
- 未读取或填写真实 API key，未发起付费模型调用，未登录 GitHub，未公开留言或提交 issue。
- 因此，AI 提取全程、模型失败重试、最终模型输出下载、登录后发帖、真实手机设备和公开部署状态均未验证。本轮不是安全渗透或科学结论复核。
- 页面实际显示 685 篇论文、5,236 条记录、35 条人工核验记录。不要把来源核验等同于独立复现或结论为真。

## P1：优先修复的已复现问题

### F1. 按“全文候选”筛选会隐藏含候选记录的人工策展论文

复现：按论文搜索 `On the Distribution of Firing Rates`。全部记录状态下，Roxin 2011 显示 16 条记录；进入详情能看到 1 条人工策展和 15 条全文候选。然后将状态切换为“全文候选”。

实际：整篇论文从结果中消失，列表为空。

影响：想核查候选的用户反而找不到已经存在的证据。单一论文状态不能替代其内部各条 claim 的状态。

建议：先筛选 claim，再按论文聚合；只要论文含有匹配候选就应保留论文。论文显示分项计数，例如“1 条策展 / 15 条候选”，不要让一条已策展记录掩盖其他候选。

验收目标：上述筛选仍返回该论文，并明确显示 15 条符合状态的候选。

截图：`.research-ingest/ux-review-2026-10-18/mixed-status-filter.jpg`。

### F2. 方向入口与论文入口的 claim 计数口径未对齐

复现：全部记录状态下，搜索同一 Roxin 论文。在“按方向”中显示“动力学与网络：1 CLAIMS / 1 PAPERS”；在“按论文”中显示 16 条记录。

实际：同一搜索、同一状态筛选，两种入口的 claim 数量相差明显，没有解释哪些候选尚未进入方向统计。

影响：读者无法判断是资料缺失、分类遗漏，还是计数错误。更大的总记录数并不保证各个入口覆盖同一批数据。

建议：使用统一的筛选和计数契约。缺少分类的候选显式放入“待分类”，或在方向统计中清楚分列人工策展、候选及未分类数量。不用机械分类来制造科学关系。

验收目标：同一筛选下，每个数量都有明确含义；不重复计数的总量可以回溯，未分类项不会静默消失。

### F3. 逻辑图默认视图拥挤，无法有效阅读，也不能键盘聚焦节点

复现：无筛选打开“逻辑图”，点击左侧 Roxin 节点。

实际：点击能更新右侧详情，但论文和命题标签被截短，中间大量节点上下重叠；图宽约 820px，与详情栏并排后可见空间更小。SVG 内未发现可聚焦的节点，节点缺少按钮/链接语义和 tabindex。

影响：结构存在，但难以作为真正的证据导航工具；键盘用户无法直接操作图节点。

建议：保留现有“论文 → claim → 问题”三列结构，不另造一种图。默认聚焦单篇论文或单个问题的邻域；提供展开更多、完整标签、选中路径高亮、适应视图及缩放。布局按节点实际高度分配空间。给节点增加可访问名称和键盘操作，并保留等价列表入口。

验收目标：默认视图节点不重叠，重要文字可读；点击或键盘选择后只突出相关链路，能查看完整命题。图中应注明当前覆盖数量与策展范围，而非让用户以为图包含全部 5,236 条记录。

截图：`.research-ingest/ux-review-2026-10-18/logic-map.jpg`。

### F4. PDF 读取“成功”没有提示数学符号已损坏

复现：提取工具选择 `2011-Journal-of-Neuroscience-Firing-Rate-Distributions-Cortical-Networks.pdf`，展开第一页原文预览。

实际：正文可读，但公式中的若干希腊字母、关系和数学符号变为控制字符或乱码。状态仍为“PDF 已读取”，未提示公式风险。

影响：这是来源质量问题，不只是排版。模型可能依据损坏的输入生成错误公式或推导，不能靠流畅的输出弥补。

建议：区分“文件读取成功”和“文本质量可用”。检测异常字符、缺字、稀疏页等质量信号，按页提示风险；对公式密集页提供 PDF 对照或可选的补充图像/OCR 路径，并重新确认发送范围及费用。不能可靠转写时保留原文定位和待人工核对状态，禁止补猜。

验收目标：这份 PDF 的异常页能被提示；读取质量和图像覆盖范围进入导出的 metadata 与报告，而不是被模型核对状态掩盖。

## P2：降低理解和参与成本

### F5. 记录与搜索状态没有可分享定位

实际选中候选 claim 后，地址仍为 `library.html?lang=en`，没有对应的 paper/claim 标识。手动搜索与模式切换也未反映在该次观察到的地址中。

建议：同步模式、搜索、筛选及选中记录的稳定 ID；提供“复制此条记录链接”和简洁引用。刷新、返回和外部分享应恢复同一位置。

### F6. 无结果时只有空白，缺少解释和恢复操作

用不存在的关键词测试，以及 F1 的状态筛选场景，结果区没有明确“找到 0 条”、当前筛选摘要或清除条件按钮。

建议：显示零结果说明、一键清除筛选、切换全部状态及同义词/检索范围提示。文案要写“当前检索未找到”，不能写成“没有人研究过”。

### F7. 英文外壳不等于英文内容

主要页面和两个教学示例能切换，但英文知识库中的多条新候选仍为中文；打开阅读报告后，也没有对应英文正文或网站的统一导航。中文社区的第三方留言组件仍显示 Write、Preview、Sign in with GitHub。

建议：把“界面语言”和“记录内容语言”明确区分。没有翻译时显示原文语言与缺失提示；未来译文需保留原记录、来源和版本。阅读报告复用轻量导航、返回论文、目录和下载入口。第三方组件不能切换时，至少用周围文案解释，或选择支持语言切换的组件。

### F8. API 工具对首次使用者仍偏技术化

实际默认表单需要填写模型 ID；完整 Chat Completions 地址位于高级设置中。请求次数、直连服务、密钥不持久化和费用说明已经存在，应保留。

建议：增加服务预设和自定义选项，明确显示将接收论文的服务与域名；说明模型 ID 从哪里获取。增加用户主动触发的连接测试，并区分配置、鉴权、跨域、配额及网络错误。连接测试是否计费也要提前说明。不要将服务私有密钥放入仓库，也不要悄悄用平台代理绕开用户选择。

未验证：本轮没有真实 provider 请求，不能声称任一运营商当前调用成功或失败。

### F9. 命中结果不解释为什么相关，长列表需要更有效的导航

按作者搜索返回很多跨年份论文；搜索 DPI 确实能找到相关论文，但列表主要显示标题、年份、状态和记录数，没有展示命中的具体 claim。

建议：显示匹配论文数/claim 数和命中片段，优先把用户带到相关命题；增加按相关性/年份排序及分页或渐进加载。不要把作者匹配、正文术语匹配与问题匹配混成没有解释的同一排序。

### F10. “按问题”覆盖范围应更透明，发现候选与确认关系应分开

当前问题入口明确限制为策展记录，这是科学上谨慎的；但它与全库总数并列时，用户容易高估问题检索的覆盖。

建议：注明问题索引覆盖了多少条策展记录；在同一页面提供“相关但未核验的候选”分区。展示候选的相关性不等于建立支持、反驳或独立复现关系，后者继续要求人工范围与来源核对。

### F11. 从阅读发现错误到贡献更正，还有断点

教学示例有更正入口，但普通候选详情没有同样直接的定位更正入口。完整 report、来源和 JSON 链接需要先返回论文详情。社区的提交入口会跳到 GitHub。

建议：每条 claim 都能生成带 paper ID、claim ID、版本、来源位置和修改理由的更正草稿；允许复制、下载或交给 Mia 申请更新。提取和提交草稿仍不能自动修改公开数据库。跳转 GitHub 前说明账号要求，并保留邮件替代路径。

### F12. 阅读深度、版本与记录编号的解释需要更清楚

Roxin 教学页明确只展示 5 条示例；完整 AI 报告有 15 条；论文容器还有原策展记录，总计 16 条。这可以是合法的不同视图，但报告内 C1 对应到论文列表时已是 CLAIM 2，若靠显示序号纠错容易指错对象。论文详情仍统一提示“这不是穷尽阅读”。

建议：把教学示例、完整文本提取和人工策展的覆盖分别标明。使用稳定 claim ID，不用当前排序序号作为身份。显示“正文文字已处理 / 图像未读 / 补充材料未提供 / 待人工核对”等具体覆盖，比单一的穷尽与否更有信息量。发表版本与实际读取的预印本版本也应并列显示。

## 产品动线建议

保留六页结构，不重新增加扩展库或平行知识库。

1. 首页只回答“这是做什么的”，给出浏览证据、免 key 看示例、提取自己 PDF 三个明确入口。
2. 方法页先给一分钟版，再展开八步细则；“怎么做”和“教学案例”继续分开。
3. 提取页按读取质量、服务确认、执行状态、候选检查、下载分步呈现。保留不自动入库的边界。
4. 示例页只承担教学展示，不以示例数量冒充整篇论文的贡献总数。
5. 知识库让方向、论文、问题、逻辑图共享同一过滤规则和可解释的计数；候选可被发现，但关系不能自动升级。
6. 社区允许建议、批评和带定位的更正；GitHub 与邮件入口都写清预期，不制造“必须学会开发才能贡献”的感觉。

## 推荐实施顺序

1. 修混合状态筛选、方向统计和空结果提示。
2. 保留三列逻辑图，修布局、聚焦、完整标签及键盘操作。
3. 增加 PDF 读取质量关口，再改善服务配置引导。
4. 增加稳定记录链接、检索命中片段和上下文更正入口。
5. 补内容语言提示、报告导航及第三方组件语言说明。
6. 在真实生效的手机视口/设备上检查导航、详情布局和图交互；真实模型调用与公开提交另行授权测试。

本轮没有重跑完整提取，没有修改任何 claim，也没有据 UI 问题判定其科学内容错误。
