# 小红书首发文案

## 标题

我想做一个“不要求科研成果先证明自己伟大”的知识库

## 正文

读博这些年，我越来越强烈地感到：很多真实、扎实的小结果，并不是没有价值，只是它们很难被包装成一篇足够宏大、足够完整、足够“有影响力”的故事。

于是我们会习惯性地把一条有限的证据，连接到机制、普适性、生物意义和应用前景；而那些无法被塞进故事的复现、负结果、边界条件和小发现，常常就消失了。

我想试着换一个科学记录的基本单位。

不是一整篇必须证明自己重要的论文，而是：

**一个清楚的观点 + 支持它的证据 + 它成立的范围 + 它不支持什么。**

我把这个开源项目叫做 **Claim Commons（观点与证据公共库）**。

它不问“这个故事够不够大”，先问四件更朴素的事：

1. 观点能不能被明确判断？
2. 证据是否真的支持它？
3. 结论在哪些条件下成立？
4. 哪些更大的推论，目前还不能从这些证据得到？

第一版已经上线。我先用 22 篇已发表论文做了一个公开试验：把每篇论文整理成一个 Paper Dossier，分别列出 bounded claim、reported evidence、scope 和 non-claim，再按主题形成可交互的观点图。

机器可以帮助寻找候选句子，但不能宣布真理。所有自动提取都必须保留原文出处，并明确标成待复核；只有人工读过全文、检查证据和边界后，才会升级为“与来源一致”。即使如此，也不等于已经独立复现。

我很希望这不是我一个人的项目。

你可以：

- 认领一篇论文，帮忙核对观点是否忠实于原文；
- 指出一句话哪里说得太强，并把它收窄；
- 补充一个没有被测试的条件或替代解释；
- 把一项复现、反证或推广连接到已有观点；
- 帮忙改进数据结构、交互和开源流程。

第一次贡献不需要会写代码。认真读一篇论文、指出一条证据的边界，就已经是在建设这个知识库。

网站：<https://mia9469.github.io/ClaimCommons/>

开源仓库：<https://github.com/Mia9469/ClaimCommons>

如果你也觉得，知识不需要先被证明伟大才有资格被记录，欢迎来 Star、Fork、提 issue，或者把这个想法转给愿意一起做的人。

**Publish the smallest defensible claim. Preserve the evidence trail. Let significance emerge.**
